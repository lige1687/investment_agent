# P0 数据可信度与基础稳定性设计

## 目标

把系统从“可能展示模拟值或模糊空状态的原型”升级为“数据不可用时宁可停止建议，也不误导交易用户”的可信基础层。

本阶段只解决四类 P0 问题：数据模式与新鲜度、前后端字段契约、空状态与错误状态、安全与页面稳定性。选基、信号、执行台账和组合穿透不在本阶段实现。

## 成功标准

1. 默认运行模式下，实时数据源失败时不得返回模拟行情。
2. 只有显式启用演示模式时才允许模拟数据，并在接口与页面同时标记。
3. 指数、板块、诊断和行情页面能够区分加载中、真实空数据、数据源失败、数据过期和演示数据。
4. 指数涨跌幅使用后端 `change_pct` 字段，页面不再把涨跌点数显示为百分比。
5. 设置页同步数据后不再因缺少数值字段调用 `toFixed` 而崩溃。
6. 飞书 Webhook 不在页面、日志或错误信息中原样回显。
7. 单个页面组件异常时显示可恢复错误页，不导致整个应用白屏。
8. 后端测试、前端测试、TypeScript 构建和关键页面浏览器复测全部通过。

## 方案选择

采用轻量“数据可信层”，不进行完整行情架构重写。

- 不采用仅修当前页面的局部补丁，因为相同的状态和字段问题会继续出现在新接口中。
- 不采用全量行情架构重构，因为超出 P0，且会放大数据源与页面回归风险。
- 通过共享元数据、前端适配器和统一状态组件建立可复用边界。

## 后端设计

### 运行模式

新增统一配置 `MARKET_DATA_MODE`：

- `live`：默认值。数据源失败时返回不可用状态，不使用 mock。
- `demo`：允许使用模拟数据，所有相关响应必须声明 `mode=demo` 和 `is_mock=true`。

不得通过请求参数临时绕过运行模式，避免普通页面误入演示数据。

### 数据状态元数据

行情类响应增加统一的 `meta`：

```json
{
  "source": "westock",
  "fetched_at": "2026-07-11T12:00:00+08:00",
  "mode": "live",
  "status": "ok",
  "stale": false,
  "is_mock": false,
  "message": null
}
```

`status` 只允许：

- `ok`：成功获得有效数据。
- `empty`：数据源成功响应，但当前确实没有数据。
- `unavailable`：数据源调用失败或没有可用来源。
- `invalid`：响应存在，但未通过字段或合理性校验。

数据源原始异常只进入服务端日志；客户端只获得可理解且不包含凭据的消息。

### 合理性校验

在服务层对进入页面和决策上下文的数据执行最小校验：

- 指数价格必须大于零。
- 涨跌幅必须是有限数值。指数默认限制为 `[-20%, 20%]`，基金与板块默认限制为 `[-30%, 30%]`；供应商有不同交易限制时通过配置覆盖，不在组件中硬编码。
- 涨跌点数与涨跌幅保持独立字段，禁止互相回填。
- 缺少关键字段时标记 `invalid`，不得进入正式交易建议。

### 模拟数据处理

保留现有 mock 生成器用于测试和演示，但必须满足：

- 仅在 `demo` 模式调用。
- 来源标记为 `demo/mock`。
- 时间戳为生成时间，但同时明确 `is_mock=true`。
- AI 决策入口遇到 mock 数据时只生成“演示建议”，不得保存成正式决策或启用正式预警。

## 前端设计

### 字段适配

建立单一 API 适配层，把后端 snake_case 显式转换为前端领域模型。例如：

```ts
change_pct -> changePct
fetched_at -> fetchedAt
is_mock -> isMock
```

组件不得直接猜测两套字段，也不得以涨跌点数作为涨跌幅后备值。

适配器负责：

- 必填字段验证。
- 数值有限性检查。
- 元数据规范化。
- 将异常响应转换为统一页面状态。

### 页面状态

新增可复用 `DataStatePanel`：

- `loading`：加载中。
- `empty`：明确说明“数据源正常，当前无数据”。
- `unavailable`：说明数据获取失败，提供重试。
- `stale`：显示最近成功时间与过期提示。
- `demo`：醒目的演示数据提示，不使用正常行情配色伪装。
- `invalid`：说明数据格式异常，本次不用于决策。

首页、行情、板块监控首先接入。选基、信号和预警占位页保留，但文案明确为“功能尚未接入”，不与真实空状态混用。

### 全局演示模式标识

只要当前页面使用演示数据，顶部显示固定的“演示数据，不可用于真实交易”标识。标识不能被普通页面操作隐藏。

### 错误边界

在路由布局外层增加全局错误边界：

- 显示出错模块和重新加载按钮。
- 不展示堆栈、请求内容或凭据。
- 记录脱敏后的前端错误。

## 设置页与凭据安全

### Webhook 展示

- GET 配置接口只返回 `configured` 和脱敏后的提示值，例如 `https://.../****abcd`。
- 前端输入框默认为空，placeholder 表示“已配置，留空则不修改”。
- 只有用户输入新值时才提交 Webhook。
- 保存、测试失败和日志均不得包含完整 URL。

### 数值防御

设置页对持仓数字使用统一格式化函数：

- `null`、`undefined`、非有限数值显示 `--`。
- 合法数值才调用格式化。
- 单条异常数据不影响其余持仓展示。

## 测试策略

### 后端

先写失败测试，再实现：

1. `live` 模式数据源失败时不会调用 mock。
2. `demo` 模式返回 mock 时元数据完整且可识别。
3. 非法涨跌幅被标记为 `invalid`。
4. 配置接口不返回完整 Webhook。
5. 留空更新不会覆盖已有 Webhook。

### 前端

引入最小 Vitest 测试环境，先写失败测试：

1. 指数适配器正确转换 `change_pct`，不使用 `change` 代替。
2. 六类数据状态映射正确。
3. 数值格式化不会对空值调用 `toFixed`。
4. Webhook 脱敏与空值保留逻辑正确。
5. 错误边界捕获子组件异常并显示恢复界面。

### 完整验证

- 后端相关测试与全量测试。
- 前端 Vitest。
- `npm run build`。
- 浏览器检查首页、行情、板块监控、设置页。
- 分别验证 live 失败与 demo 两种模式。

## 兼容与迁移

- 保持现有业务数据表不变。
- API 新增 `meta`，现有数据字段继续保留，降低一次性迁移风险。
- 前端通过适配器完成字段迁移，组件只依赖规范化模型。
- 旧的完整 Webhook 配置继续保存在后端，但读取接口不再返回原值。

## 非目标

- 不实现自动交易或券商下单。
- 不实现新的选基、信号或预警业务规则。
- 不重写所有数据供应商。
- 不调整现有仓位策略和回测算法。
- 不将演示数据删除；只隔离并明确标识。

## 风险与回滚

- 严格模式可能让部分原本“看起来有数据”的页面变成不可用状态，这是预期行为。
- 通过 `MARKET_DATA_MODE=demo` 保留演示和开发能力。
- 前端适配器逐页接入；未迁移页面继续使用原接口，避免大爆炸式改造。
- 若新增元数据影响旧客户端，可在后端保留原数据顶层结构，仅新增 `meta` 字段。
