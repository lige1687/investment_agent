# 今日交易讨论室渐进式输入设计

## 背景

当前讨论室在“开始今日讨论”之前要求填写可用现金、账户近期峰值、在途买入和今日已申购。页面同时已经从养基宝读取同步持仓，因此这组前置输入让日常讨论显得重复且沉重，也会让“不操作”和“只观察”的讨论承担本来不需要的执行信息成本。

本设计是对《每日基金交易讨论室体验版设计》中“上下文快照”和“最终金额校验”交互的补充。数据可信边界、影子运行、手动确认和不自动下单原则保持不变。

## 目标

- 日常入口改为一键开始讨论，不重复录入已经同步的持仓。
- 只有明确买入机会需要计算金额时，才向用户确认真正必要的执行数据。
- 目标仓位确认一次后持续沿用，不按日、按月或页面刷新重复询问。
- 对缺失的现金和回撤数据诚实降级，不用默认值制造可执行金额。
- 保留低频异常订单入口，但不让它占据主流程。

## 非目标

- 本次不接入支付宝、天天基金或券商订单 API。
- 不声称养基宝当前能够提供可用现金、未确认订单或销售渠道当日申购累计。
- 不自动修改用户已经确认的目标仓位。
- 不因隐藏输入而放松最终金额的服务端复算和申购状态预检。

## 选定方案

采用“先分析、后按需确认”的渐进式交互：

1. 首屏自动读取同步持仓，只显示同步状态和“开始今日讨论”。
2. 市场阶段、持仓风险、不操作、观察和卖出讨论不要求填写现金或订单信息。
3. 只有专业 Agent 形成明确买入建议，并且其余可信条件允许计算金额时，才进入资金确认。
4. 资金确认默认只展示可用现金；在途买入和今日已申购藏在低频例外入口中。
5. 未完成资金确认时可以买入方向和条件，但不能展示“立即可执行”的最终金额。

## 页面与交互

### 讨论前

页面顶部显示一行账户上下文状态：

- 已同步持仓数量。
- 持仓总市值。
- 同步时间或“同步时间未知”。
- 数据来源与可信状态。

主操作只保留：

- `开始今日讨论`
- `只读分析，不会自动下单`

移除可用现金、账户近期峰值、在途买入和今日已申购四个前置输入框。

持仓为空、未连接或数据过期时，按钮旁显示明确原因和前往同步入口；不得用空持仓冒充真实账户启动正式讨论。

### 讨论后

- `NO_ACTION`、`WATCH`、卖出建议：直接展示结论，不出现资金确认。
- 明确买入但数据或风险条件不满足：展示条件与缺失项，不出现可执行金额。
- 明确买入且只缺执行资金：展示紧凑的“确认可买金额”区域。

资金确认区域包含：

- 可用现金：必填，允许带入上一次确认值，但必须显示确认时间；上一次值不能直接作为本次可执行依据。
- `有未确认订单或今天已买过这只基金`：默认收起的低频入口。
- 展开后可填写账户级在途买入金额，以及本次拟买基金在当前渠道的今日已申购金额。

用户已确认其日常基本没有重复申购和在途订单，因此收起状态按两项均为 0 计算，并在金额说明中显示“按无在途买入、今日未申购计算”。用户可以在确认金额前展开修正。

## 四项数据的处理规则

### 持仓与持仓市值

继续使用现有养基宝本地同步持仓，不提供重复手填入口。讨论快照保留持仓来源、同步状态和时间。正式金额复算时仍以服务端保存的讨论快照为基础，不接受前端自行扩大或删除持仓金额。

### 可用现金

养基宝当前持仓响应没有可靠的可用现金字段，因此不能从持仓市值反推现金。

- 分析阶段允许未知。
- 最终买入金额阶段必须由用户确认。
- 最近确认值只用于预填和提醒，必须带确认时间。
- 未确认时，`LightTradeGuard` 不得生成立即可执行金额。

### 在途买入

定义为已经提交但尚未确认份额、仍会占用现金并形成未来仓位的买入订单。它是账户级资金占用，最终复算时从可用现金中扣减。

默认值为 0，仅作为用户已经确认的低频使用习惯，不伪装成来自订单 API 的事实。页面必须保留可展开的修正入口。

### 今日已申购

定义为当前自然日内，对“本次拟买基金 + 当前销售渠道”已经提交的申购金额。它用于扣减基金管理人或渠道的当日剩余申购限额，不是账户级统一金额。

默认值为 0，仅在买入确认区域按拟买基金收集。不得继续使用一个全局“今日已申购”输入影响所有基金。

### 账户近期峰值

不再要求用户每日填写。系统新增只读的账户估值快照，用可信的同步持仓市值和当时已确认现金形成账户权益记录，并从连续快照中计算近期峰值。

- 没有足够历史或现金未知时，回撤指标标记为 `UNKNOWN` 或低置信度。
- 回撤未知不阻止市场和持仓分析。
- 回撤未知不得触发确定性的账户减仓结论，也不得被当作“当前无回撤”。
- 后续获得更完整的账户总资产同步能力后，可以替换估值来源，不改变页面交互。

## 目标仓位生命周期

目标仓位属于长期交易政策，不属于每日上下文。

- 第一次没有任何已确认政策时确认一次。
- 页面刷新、重新登录、第二天再次讨论和持仓正常变化都不触发重新确认。
- 当前政策以紧凑摘要显示，详细阈值放入“查看策略”。
- 只有用户点击“调整策略”才修改已有目标。
- 出现未配置的新题材时，允许先完成阶段分析；只有该题材形成明确买入建议并需要金额时，才询问一次该题材目标仓位。
- Agent 只能提出调整建议，不能自动覆盖现有目标仓位。

## 数据流

```text
进入讨论室
  -> 读取当前已确认交易政策
  -> 读取养基宝本地同步持仓与同步状态
  -> 展示一键开始入口
  -> 创建不可变讨论上下文（现金允许未知）
  -> 专业 Agent 讨论市场阶段、持仓和方向
  -> 非买入结论：直接结束，不询问资金
  -> 明确买入结论：刷新申赎预检
  -> 确认可用现金；低频订单信息默认收起
  -> 服务端复算限购、现金、在途资金和目标仓位
  -> 展示护栏后的可执行区间或不可执行原因
```

## 组件与接口调整

### 前端

- `TradingRoomPage` 删除四个前置金额状态和输入框。
- 启动按钮上方新增同步账户摘要。
- `DecisionDraftPanel` 在明确买入且缺少资金确认时展示按需确认组件。
- `PolicyImportPanel` 的已就绪状态改为一行摘要，并提供“查看/调整”入口。
- 新增低频订单折叠区；默认不占页面空间。

### 后端

- 讨论上下文允许 `cash` 和 `peak_equity` 在分析阶段未知，但通过明确的可信状态和 blocker 表达，不再用 0 或当前权益伪装成已确认值。
- 最终买入金额接口接收本次现金确认、账户级在途买入和基金级今日已申购，并在服务端重新计算。
- 保存现金确认时间和适用讨论，便于下次预填但不自动授权执行。
- 新增账户估值快照存储与近期峰值计算；来源不完整时返回低置信度或未知。
- 当前政策继续使用数据库中最新的已确认版本，不为每日讨论创建空目标政策。

## 失败与降级

- 持仓未同步：不启动正式实盘讨论，提示先同步。
- 持仓同步时间未知：允许解释性讨论，正式可执行状态降级。
- DeepSeek 不可用：保留上下文并显示专业席位不可用，不生成假结论。
- 没有可用现金确认：可以买入方向和触发条件，但最终金额不可执行。
- 没有账户峰值历史：回撤显示未知，不阻止其他分析，也不假定回撤为 0。
- 未配置新题材目标：阶段分析继续；买入金额阶段才请求目标仓位。

## 测试与验收

### 前端

- 已同步持仓时，首屏不存在四个金额输入框。
- 一键开始会自动携带同步持仓。
- 不操作、观察和卖出结果不出现资金确认。
- 明确买入结果只显示可用现金确认，低频订单信息默认折叠。
- 已确认目标仓位在刷新和新讨论中不重复询问。

### 后端

- 未知现金不能生成立即可执行买入金额。
- 今日已申购按基金和渠道扣减限购，不影响其他基金。
- 在途买入只扣减账户可用现金并计入未来仓位。
- 账户峰值缺失时回撤为未知，而不是 0。
- 当前已确认政策跨会话持续返回，只有显式修改生成新版本。

### 浏览器验收

1. 打开讨论室，只看到同步账户摘要和开始按钮。
2. 发起一次不操作场景，过程中不出现资金输入。
3. 发起一次明确买入场景，在最终金额前才出现现金确认。
4. 展开低频订单入口，验证两项金额的作用范围和说明。
5. 刷新页面并再次进入，目标仓位不被重复询问。
